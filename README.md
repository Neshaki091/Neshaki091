## 🚀 Featured Engineering Projects

### 1. 🔬 ARQ-RAG: Adaptive Retrieval with Quantization
**Graduate Thesis (Score: 9.0/10)** | *Research paper submitted to AMI2026*  
**Tech Stack:** `Rust` · `SIMD (AVX2)` · `Vector Quantization` · `IVF` · `mmap` · `Python` · `RAG`  
**Repository:** [github.com/neshaki091/arq-rag](https://github.com/neshaki091/arq-rag) *(Code & thesis artifacts)*

> **Problem**: Storing and searching massive high-dimensional vector embeddings in RAG systems creates a critical "memory wall", resulting in heavy RAM footprint and retrieval latency bottlenecks.

```
┌─────────────────┐     ┌────────────────────────────────────────────────────────┐
│ High-Dim Vector │────▶│ ARQ-RAG Retrieval Core (Rust + SIMD AVX2)              │
│   (Float32)     │     │  ┌───────────────────────┐  ┌───────────────────────┐  │
└─────────────────┘     │  │ TurboQuant + IVF Index│  │ Precomputed LUT (ADC) │  │
                        │  └───────────┬───────────┘  └───────────┬───────────┘  │
                        │              │                          │              │
                        │              ▼                          ▼              │
                        │  ┌──────────────────────────────────────────────────┐  │
                        │  │ SIMD Cluster-centric Scan & Query Batching (mmap)│  │
                        │  └──────────────────────────────────────────────────┘  │
                        └───────────────────────────┬────────────────────────────┘
                                                    ▼
                                     Top-K Documents / Context
```

- **Low-Level SIMD Retrieval Core (Rust)**: Designed and implemented a custom vector quantization and retrieval engine in Rust, utilizing **AVX2 256-bit SIMD intrinsics** for parallelized asymmetric distance computation.
- **TurboQuant + IVF Integration**: Synthesized TurboQuant vector compression with an **Inverted File Index (IVF)**, introducing coarse cluster pruning to TurboQuant for scalable search spaces.
- **Memory Footprint Reduction with `mmap`**: Integrated memory-mapped file I/O (`mmap`) to query large quantized index files directly from disk cache without holding all compressed vector data in active RAM.
- **Cache Locality & Query Batching**: Built a **Cluster-centric Scan** mechanism combined with **Query Batching** to group queries targeting identical centroid partitions, maximizing CPU L1/L2/L3 cache reuse.
- **Quantization Pipeline**:
  - **ITQ (Iterative Quantization)** with orthogonal rotation to minimize quantization distortion.
  - **Max-Lloyd scalar quantization** combined with percentile-based outlier clipping (P01–P99) to preserve dynamic range.
  - **Asymmetric Distance Computation (ADC)** via precomputed Lookup Tables (LUT).
- **Experimental Setup & Evaluation**:
  - **Baseline**: Uncompressed Float32 vector retrieval.
  - **Evaluation Metric**: $\text{Recall@K} = \frac{|\text{TopK}_{\text{compressed}} \cap \text{TopK}_{\text{Float32}}|}{K}$
  - **Datasets**: Meta Wikipedia 5M vector dataset, HotpotQA, Qasper, and Vietnamese Transport Law dataset.
  - **Measured Dimensions**: Recall@K, Latency, QPS, Memory footprint, and Vector encoding time `[BENCHMARK DATA AVAILABLE IN THESIS/PAPER]`.

### 2. 💧 Waterbase: Self-Hosted Multi-Tenant Backend-as-a-Service (BaaS)
**Graduation Internship Project / Sole Developer** | **Live App:** [tttn-project-waterbase-mini-clone-f.vercel.app](https://tttn-project-waterbase-mini-clone-f.vercel.app/)  
**Tech Stack:** `Node.js` · `Express` · `MongoDB` · `Redis` · `Docker Compose` · `Nginx (API Gateway)` · `WebSocket (RTWaterDB)`

> **Overview**: Researched and developed end-to-end as a graduation internship project, Waterbase is a lightweight, self-hosted Backend-as-a-Service (BaaS) platform designed for multi-tenancy and low-resource infrastructure (currently running all 7 services in production on a minimal 1GB RAM / 1 vCPU VPS).

```
                     ┌───────────────────────────────┐
                     │         Nginx Gateway         │
                     │  (Reverse Proxy • SSL • Auth) │
                     └───────────────┬───────────────┘
                                     │
    ┌────────────────────────────────┴────────────────────────────────┐
    │           7 Decoupled Microservices (Docker Compose)            │
    │  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌─────────┐ │
    │  │ auth-services│ │ app-services │ │  waterdb-svc │ │rtwaterdb│ │
    │  └──────────────┘ └──────────────┘ └──────────────┘ └─────────┘ │
    │  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐           │ │
    │  │ storage-svc  │ │ rule-engine  │ │analytics-svc │           │ │
    │  └──────────────┘ └──────────────┘ └──────────────┘           │ │
    └────────────────────────────────┬────────────────────────────────┘
                                     │
                     ┌───────────────┴───────────────┐
                     │   MongoDB • Redis (Cache)     │
                     │  (Database-per-Application)   │
                     └───────────────────────────────┘
```

- **7-Service Microservices Architecture**: Auth Service, App Service, WaterDB, RTWaterDB (Realtime), Storage, Rule Engine, and Analytics orchestrated via Nginx API Gateway.
- **Database-per-Application Multi-Tenancy**: Dedicated MongoDB databases dynamically provisioned per tenant application, strictly isolating tenant data and preventing cross-application data leaks.
- **Declarative Rule Engine & RBAC**: JWT credential validation combined with dynamic expression-based security rule compilation for fine-grained, collection-level read/write access control.
- **Realtime Synchronization & Low-Spec VPS Deployment**: Bi-directional streaming via WebSocket (RTWaterDB) with full Docker Compose containerization, running reliably on ~3GB RAM servers.

### 3. 📚 EduChatbot: Vietnamese RAG Courseware Assistant
**Java Course Project** | **Role:** Team Leader (6 Members) & Backend Architect  
**Tech Stack:** `Java 17` · `Spring Boot 3.x` · `Spring Security` · `LangChain4j` · `Python` · `FastAPI` · `Qdrant` · `pgvector` · `React`

> **Problem**: University students need accurate, subject-scoped institutional answers, while the university requires verifiable accuracy and a benchmark comparing RAG vs Fine-tuning.

```
   [React Client] ──▶ [Spring Boot 3 Server (Java 17)]
                              │
            ┌─────────────────┴─────────────────┐
            ▼                                   ▼
    [Spring Security + JWT]             [LangChain4j RAG Core]
    (Student / Admin RBAC)            (Query Rewriting + Qdrant)
            │                                   │
            ▼                                   ▼
   [Supabase / pgvector]             [FastAPI Bridge (Python)]
   (Document & Metadata Store)       (LoRA Fine-Tuned Model)
```

- **Team Leadership & System Architecture**: Led a team of 6 engineers. Authored the **System Requirements Specification (SRS)**, designed the **Database Owner Matrix**, established coding conventions, and conducted technical code reviews.
- **Spring Boot 3 Backend Architecture**: Built the core system with Java 17 and Spring Boot 3.x, incorporating **Spring Security** (JWT authentication, refresh tokens), Student/Teacher/Admin role-based access control (RBAC), global exception handlers, and unified API response schemas.
- **RAG Ingestion & Vector Retrieval Pipeline**:
  - Parsed unstructured documents (PDF, DOCX, TXT) using **Apache Tika** paired with a custom Vietnamese text splitter.
  - Implemented semantic retrieval using **LangChain4j**, query rewriting via LLM (Llama 3.1), and subject-scoped vector filtering on **Qdrant**.
- **Java-Python Microservice Bridge**: Integrated Spring `WebClient` to connect asynchronous Java backend workflows with a Python **FastAPI** service serving LoRA fine-tuned models.
- **Evaluation & A/B Testing**: Implemented a blind side-by-side comparison system (RAG vs. Fine-tuning) and automated **LLM-as-a-Judge** evaluation to assess answer faithfulness and hallucination rates.
